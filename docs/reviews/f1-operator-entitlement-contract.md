## 3. Desain yang direvisi: satu rutin sebagai satu-satunya jalur grant

Satu rutin: app.grant_module_entitlement(p_workspace_id uuid, p_module_id text, p_version text, p_reason text) RETURNS TABLE(result text, workspace_id uuid, module_id text, version text, granted_by text, granted_at timestamptz, audit_present boolean), LANGUAGE plpgsql, VOLATILE, SECURITY DEFINER, SET search_path = pg_catalog, pg_temp. Pemilik: umnia_grant_exec (NOLOGIN, NOSUPERUSER, NOBYPASSRLS — peran eksekusi/pemilik yang ketat, bukan superuser dan bukan anggota peran lain). Semua referensi objek di dalam rutin memakai nama terkualifikasi skema (public.*, pg_catalog.*); tanpa SQL dinamis (tanpa EXECUTE/format) kecuali satu EXECUTE di dalam blok DO migrasi untuk membuat rutin itu sendiri; tanpa membaca GUC pemanggil apa pun.
Mengapa SECURITY DEFINER dan mengapa pemilik NOLOGIN: rutin berjalan dengan hak pemiliknya, sehingga pemanggil yang tidak punya DML tabel tetap bisa memakai satu operasi istimewa yang sempit (pola otorisasi batas yang didokumentasikan PostgreSQL). Pemilik superuser dilarang eksplisit oleh panduan CREATE FUNCTION kecuali benar-benar butuh kekuatan superuser — rutin ini tidak butuh. Pemilik NOLOGIN berarti tidak ada yang bisa login sebagai pemilik; satu-satunya kode yang berjalan dengan hak itu adalah tubuh rutin yang statis.
Peran: umnia_operator = grup kapabilitas NOLOGIN (pemegang EXECUTE atas rutin + USAGE atas skema app); umnia_op_<id> = satu role LOGIN NOSUPERUSER NOBYPASSRLS per operator manusia, anggota grup umnia_operator, dibuat deployment (bagian 6); umnia_grant_exec = pemilik rutin NOLOGIN di atas. TIDAK ADA keanggotaan operator pada peran pemilik; TIDAK ADA keanggotaan umnia_business/umnia_admin pada grup operator; kredensial runtime bisnis/admin tidak pernah bisa menjadi operator (bagian 6 melarang pemberian keanggotaan itu).
Identitas aktor: audit actor = session_user, yaitu role LOGIN yang mengautentikasi koneksi — nilai ini tidak berubah oleh SET ROLE maupun oleh SECURITY DEFINER (current_user di dalam rutin adalah pemilik, bukan manusia; karena itu current_user TIDAK PERNAH dipakai sebagai identitas audit). CLI tidak lagi menerima flag --operator dan tidak menerima --source; tidak ada GUC identitas yang diset pemanggil. granted_by pada baris entitlement = 'operator:' || session_user; operator_id pada baris audit = session_user. Rutin juga menjaga dirinya sendiri: memeriksa pg_has_role(session_user, 'umnia_operator', 'member') pada setiap pemanggilan; bila bukan anggota, RAISE EXCEPTION sebelum menyentuh data — jadi kalaupun EXECUTE entah bagaimana diberikan lebih luas, rutin tetap menolak pemanggil non-operator.
Tabel audit operator (diimplementasikan, migrasi 011): operator_audit_events di DB umnia_business (satu transaksi dengan baris entitlement; DB admin tidak punya skema dan atomicity lintas-DB tidak ada tanpa 2PC). Kolom: id UUID PK default gen_random_uuid(), workspace_id UUID NOT NULL REFERENCES workspaces(id), module_id TEXT NOT NULL, version TEXT NOT NULL, operator_id TEXT NOT NULL (session_user, BUKAN FK ke identity_subjects), action TEXT NOT NULL CHECK (action IN ('entitlement_granted')), source TEXT NOT NULL, reason TEXT NOT NULL, result TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(). Trigger append-only memakai fungsi khusus app.reject_operator_audit_change() (pesan 'operator_audit_events is append-only', terpisah dari app.reject_audit_change() milik 002). audit_events tetap tidak bisa dipakai: actor_subject_id NOT NULL REFERENCES identity_subjects(id) — operator bukan subjek bisnis; membuat subjek palsu atau mengatribusikan grant ke pemilik adalah pemalsuan audit.

## 4. Kontrak rutin dan CLI (diimplementasikan, migrasi 011 + cmd/grant-entitlement)

Input rutin: p_workspace_id uuid (format UUID ditegakkan tipe); p_module_id text (1-128 karakter, tidak kosong); p_version text (1-64 karakter, tidak kosong); p_reason text (1-500 karakter sesudah trim, wajib tidak kosong). source BUKAN input: rutin mengisi konstanta 'operator-cli' pada kedua INSERT. Kode galat kustom: U11NR (not ready), U11IV (invalid), U11NF (not found), U11CF (conflict) — kode kelas U0 adalah kode galat buatan aplikasi yang sah di PostgreSQL; CLI memetakannya ke pesan tetap dan kode keluar, tanpa mencetak teks galat mentah.
Langkah tubuh rutin, berurutan, dalam satu pemanggilan (satu pernyataan = satu transaksi implisit; exception apa pun me-rollback semuanya): (a) Marker 011 diperiksa DI DALAM rutin sebelum mutasi apa pun (amendemen A): bila schema_migrations tidak berisi '011_operator_entitlement', galat not_ready U11NR — DB tanpa marker gagal tertutup meski rutinnya ada. Hanya peran eksekutor yang mendapat SELECT(version) atas schema_migrations. (b) v_actor := session_user; tolak bila bukan anggota umnia_operator (U11NR). (c) Validasi batas input; tolak bila NULL/di luar batas (U11IV). (d) Gate modul: modul harus 'rental.basic', bila bukan, galat invalid (U11IV) — sebelum kunci/baris dibaca. (e) Kunci baris workspace: SELECT id FROM public.workspaces WHERE id = p_workspace_id FOR UPDATE — kunci yang sama dengan aktivasi (modules.go:156), sehingga grant dan aktivasi pada workspace yang sama terserialisasi; tidak ada baris = workspace tidak ditemukan, galat U11NF, tanpa tulis. (e2) Gate versi SEBELUM cabang baris yang ada: versi yang diminta harus '0.1.0', bila bukan, galat invalid (U11IV) — permintaan versi selain 0.1.0 selalu invalid, apa pun isi baris yang ada (koreksi review F8: urutan asli menaruh gate ini sesudah konflik, sehingga legacy 0.2.0 + permintaan 0.2.0 lolos sebagai sukses di luar scope beku). (f) Baca entitlement yang ada untuk (workspace, 'rental.basic'): versi berbeda dari yang diminta (kini hanya mungkin 0.1.0 diminta vs versi lain yang ada) = galat konflik U11CF, tanpa tulis; versi sama = kembalikan 'already_granted' bila ada event audit ASLI untuk baris itu, atau 'legacy_existing' bila tidak ada — tanpa tulis apa pun, tanpa menulis ulang granted_by/source/reason, tanpa mengatribusikan grant lama ke pemanggil baru; versi yang dikembalikan adalah versi baris yang ada (bukan hardcode 0.1.0). 'Asli' di sini berarti provenance lengkap: event audit harus cocok dengan baris entitlement pada aktor ('operator:' || operator_id = granted_by), source, reason, DAN waktu (created_at = granted_at; now() stabil dalam satu transaksi) — event grant lain dengan workspace/modul/versi/action sama tidak dihitung (koreksi review F7). (g) Validasi tuple katalog ada di public.module_registry (rental.basic/0.1.0); tidak ada = galat not_found U11NF. (h) INSERT entitlement (granted_by 'operator:' || v_actor, source 'operator-cli', reason sesudah trim) + INSERT audit (operator_id v_actor, action 'entitlement_granted', source 'operator-cli', reason, result 'granted'); kembalikan result 'granted', audit_present true. (i) Rutin tidak pernah menyentuh module_installations.
Hasil CLI: exit 0 + satu baris (granted / already_granted / legacy_existing) dengan workspace, modul, versi, granted_by, granted_at (RFC3339), audit_present; galat: exit bukan 0 + satu baris pesan tetap — 'invalid:'/'not_found:'/'not ready:' = exit 2, 'conflict:' = exit 3, lainnya = exit 1; tanpa tulis apa pun pada semua galat. DSN/password/alasan tidak pernah muncul di output. Koneksi putus sesudah submit = 'outcome unknown' (exit 1): hasil tidak diketahui, bukan rollback yang dijamin; jalankan ulang untuk mengamati state — CLI tidak pernah retry tulis buta.
CLI (diimplementasikan): binary grant-entitlement dari services/business-api/cmd/grant-entitlement/main.go. Memakai ulang pgx yang sudah menjadi dependensi langsung; tanpa dependensi baru, tanpa perubahan handler/API/web. Pemanggilan: grant-entitlement --workspace <uuid> --module rental.basic --version 0.1.0 --reason "<wajib>". ## 5. Tabel ACL/RLS per peran (diimplementasikan; semua grant eksplisit, tanpa default)

Peran umnia_business (runtime API): tidak berubah — SELECT module_entitlements; SELECT/INSERT/UPDATE module_installations; SELECT module_registry; TANPA EXECUTE atas rutin; TANPA akses operator_audit_events; TANPA INSERT entitlement. Peran umnia_admin (aplikasi admin): TANPA EXECUTE atas rutin; TANPA akses apa pun ke tabel bisnis operator. Peran bootstrap/superuser (umnia_bootstrap, postgres): deployment saja (migrasi, pembuatan peran); BUKAN pemanggil rutin operasional dan BUKAN pemilik rutin.
Peran umnia_op_<id> (LOGIN per operator): CONNECT ON DATABASE umnia_business; USAGE ON SCHEMA app; EXECUTE ON FUNCTION app.grant_module_entitlement(uuid, text, text, text); TIDAK ADA hak tabel apa pun (tanpa SELECT/INSERT/UPDATE/DELETE atas workspaces, module_registry, module_entitlements, operator_audit_events, schema_migrations); TIDAK ADA USAGE atas skema public; TIDAK ADA keanggotaan pada umnia_grant_exec.
Grup umnia_operator (NOLOGIN): pemegang EXECUTE atas rutin + USAGE ON SCHEMA app; keanggotaan diberikan deployment kepada tiap umnia_op_<id>; mencabut keanggotaan mencabut kapabilitas.
Peran umnia_grant_exec (NOLOGIN, pemilik rutin): USAGE ON SCHEMA app, public; SELECT (id) + UPDATE (id) atas public.workspaces — UPDATE satu kolom adalah syarat hak kunci FOR UPDATE menurut dokumentasi SELECT PostgreSQL 16 (SELECT saja tidak cukup); SELECT atas public.module_registry; SELECT + INSERT atas public.module_entitlements; SELECT + INSERT atas public.operator_audit_events; SELECT (version) atas public.schema_migrations (hanya peran ini, amendemen A); CREATE ON SCHEMA app hanya sementara di dalam blok DO migrasi untuk pengalihan kepemilikan fungsi, lalu dicabut sebelum commit (amendemen D); TIDAK ADA hak lain, TANPA DELETE/UPDATE baris, TANPA BYPASSRLS/superuser. Urutan di migrasi: validasi peran dulu, lalu OWNER TO, baru GRANT (pelajaran F1-FOUNDATION-REMEDIATION yang TERBUKTI: GRANT sebelum OWNER TO hilang oleh pengalihan pemilik).
Kebijakan RLS (diimplementasikan, semua TO peran yang disebut; kebijakan membership yang ada tidak disentuh): workspaces — FOR SELECT TO umnia_grant_exec USING (true) DAN FOR UPDATE TO umnia_grant_exec USING (true). Dua-duanya wajib: tabel Policies Applied by Command Type pada CREATE POLICY menyatakan SELECT FOR UPDATE/SHARE memeriksa kebijakan SELECT (baris terlihat) DAN kebijakan UPDATE (baris yang boleh dikunci); tanpa keduanya kunci gagal diam-diam (nol baris) atau ditolak. module_entitlements — FOR SELECT TO umnia_grant_exec USING (true); FOR INSERT TO umnia_grant_exec WITH CHECK (true). operator_audit_events — FOR SELECT TO umnia_grant_exec USING (true) (untuk cek legacy); FOR INSERT TO umnia_grant_exec WITH CHECK (true). module_registry — tanpa RLS (003), cukup hak SELECT. operator_audit_events — REVOKE ALL lalu GRANT INSERT + SELECT hanya ke umnia_grant_exec; tanpa grant ke umnia_business atau ke PUBLIC. Rutin: REVOKE ALL ON FUNCTION app.grant_module_entitlement(uuid, text, text, text) FROM PUBLIC, lalu GRANT EXECUTE hanya ke umnia_operator (fungsi baru defaultnya EXECUTE untuk PUBLIC — pencabutan ini wajib, bukan opsional). Hak PUBLIC yang sudah ada sebelumnya atas schema_migrations TIDAK ditulis ulang (amendemen A): tidak adanya GRANT individual bukan penolakan yang efektif karena hak PUBLIC diwarisi; yang dibuktikan adalah ACL aktual (proacl rutin tanpa entri PUBLIC; has_function_privilege/has_column_privilege pada tes, bagian 11).
Migrasi 011 (diimplementasikan): tidak memakai BEGIN/COMMIT (pemanggil -1 sudah membungkus; COMMIT di dalam akan merusak transaksi luar). Validasi peran di blok DO PERTAMA, sebelum perubahan apa pun: umnia_operator + umnia_grant_exec harus ada dan NOLOGIN/NOSUPERUSER/NOBYPASSRLS/NOCREATEROLE/NOCREATEDB/NOREPLICATION; umnia_grant_exec tidak boleh menjadi anggota peran lain; TIDAK ADA yang boleh menjadi anggota umnia_grant_exec; umnia_operator tidak boleh menjadi anggota peran lain; umnia_business/umnia_admin tidak boleh menjadi anggota umnia_operator atau umnia_grant_exec — pemeriksaan keanggotaan bisnis/admin memakai JOIN nama peran (pg_roles), bukan cast 'umnia_admin'::regrole, karena cast gagal pada klaster bisnis-saja yang tidak berisi umnia_admin (koreksi lanjutan F2; kedua daftar peran segar CI dan klaster bisnis Windows memang tidak berisi peran itu); setiap anggota umnia_operator harus LOGIN least-privilege (koreksi review F1 — seed yang tidak aman tidak diadopsi diam-diam; koreksi lanjutan: ketiga skrip provisioning menjalankan PREFLIGHT lengkap SEBELUM mutasi apa pun dan MENOLAK tabrakan yang tidak aman dengan galat tersanitasi tanpa mengubah state — tidak ada REVOKE/ALTER atribut perbaikan; rotasi password yang disengaja pada peran sehat tetap diizinkan sesudah preflight lolos); setiap anggota umnia_operator dan setiap login roster HANYA boleh menjadi anggota umnia_operator — allowlist parent (koreksi ACL-PREFLIGHT-EVIDENCE): parent kustom NOLOGIN yang memberi hak kolom lewat pewarisan (mis. SELECT(id)) lolos dari pemeriksaan has_table_privilege (tidak melihat hak kolom) dan attacl LIKE login langsung (entri tercatat atas nama parent), sehingga satu-satunya pertahanan adalah menolak parent apa pun selain umnia_operator sebelum mutasi; umnia_business harus ada; bila tidak, RAISE EXCEPTION (gagal tertutup). Database baru PG16 tidak lagi memberi CREATE atas skema public kepada PUBLIC (PostgreSQL 15 Release Notes) — lapisan tambahan, bukan satu-satunya pertahanan: rutin tidak bergantung pada default itu, karena semua nama terkualifikasi dan search_path dipatok. ## 7. Semantik (grant baru vs no-op vs konflik vs legacy)

Grant baru: result 'granted'; satu baris entitlement + satu baris audit, atomik; granted_by 'operator:' || session_user; source 'operator-cli'; reason persis input (sesudah trim, 1-500 karakter).
Sama-versi dengan audit: result 'already_granted'; tanpa tulis; granted_by/granted_at/source/reason ASLI dikembalikan apa adanya, tidak ditulis ulang, tidak diatribusikan ke pemanggil baru.
Sama-versi tanpa audit (legacy/manual/QA, mis. baris helper tes 'operator:fixture'): result 'legacy_existing'; tanpa tulis; TANPA memfabrikasi baris audit asal untuk baris itu — ketiadaan audit adalah fakta yang dilaporkan, bukan kekosongan yang diisi. Pemanggil yang butuh kepastian asal baris legacy memeriksanya di luar band (catatan deployment), bukan lewat tulis.
Versi berbeda (modul yang sama): galat 'conflict:'; tanpa tulis; baris lama utuh. Urutan evaluasi (amendemen B + koreksi review F8): gate modul, lalu kunci workspace, lalu gate versi 0.1.0, lalu konflik/no-op pada baris yang ada — sehingga permintaan versi selain 0.1.0 SELALU invalid (apa pun baris yang ada), sedangkan permintaan 0.1.0 pada baris versi berbeda menghasilkan conflict.
Input tidak valid atau modul/versi tidak didukung: galat 'invalid:'/'not_found:'; tanpa tulis. Modul selain rental.basic selalu invalid, meski ada baris sintetis modul itu. Tidak ada framework replay/billing generik: replay di sini hanya nama untuk no-op duplikat persis di atas.
